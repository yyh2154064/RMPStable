首次灰屏修复检查真实 Win32 层级，必要时把副本放到本体上方，保留其他前台窗口、不激活。早期尝试中曾写反 GW_HWNDPREV/GW_HWNDNEXT，自动化的早期“通过”不能证明可见显示；用户反馈后已纠正，图形后端保持原设置。最终判断结合正确层级检查和用户可见确认，不仅凭 drawFrames 或副本本地截图。Microsoft 常量定义见 [GetWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindow)。

计时偏差来自副本原版独立 RunManager 的检查点时长与加载/暂停时钟，而时间字段本来被排除在对局 hash 外。现在通过认证通道、当前 generation 发送本体原版计时标签；副本原版标签跟随该值，不改本体时钟、存档或结算。每次秒跳只发送变化，存在正常进程通信延迟，不承诺两个进程在同一瞬间刷新。计时测试最初两次失败为测试字段名称不适配当前版本，修正为 `_prevSessionRunTime` 后取得上述最终结果。

所有专项只使用已有 F 盘隔离 runtime、最小档案和认证自有窗口，结束清理专项 profile、保留证据。交付桌面四文件 mod 文件夹，等待用户最终手动验收；用户只确认了灰屏修正可见，不将整个 `.13` 或其他专项自行标记为已验收。
