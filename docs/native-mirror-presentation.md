# 本体与原生副本的呈现同步讨论（2026-10-09）

当前两个进程分别运行原版场景，模型决策只有本体具备权威。操作日志重建对局，不包含完整的本体展示状态。窗口原版鼠标悬浮和独立看牌使用自己的鼠标/页面，因此仅有模型及决策一致，并不能自动重现本体 hover、牌堆查看、滚动位置和动画进度。.7 修复交互缺陷，没有实现下述完整跟随模式。

可以在当前架构增加独立的呈现消息，传本体归一化鼠标坐标、语义卡牌/控件身份、查看页面、排序及滚动位置。副本仍调用原版控件，保持不回传画面、不重绘游戏的边界。Deck、Hand、Draw、Discard、Exhaust 等页面需绑定原版对应牌堆；开启、关闭、升级预览和卡牌检查不能误触选择任务或再次执行游戏动作。

建议观战时跟随本体指针和展示页面，控制时让窗口鼠标负责当前操作；本体输入和窗口输入需有明确优先级。鼠标连续位置可以合并为最新一条，页面开启/关闭需有序且带 generation。hover 引起的界面标记不改变真实存档或权威模型。已有跨进程语义控件键和原生鼠标位置入口可复用，但需验证拖牌目标选择、弹窗遮挡、地图滚动及快速切页。

可以做到使用体验上很接近第二个本体；仅靠事件重放，无法承诺两个独立进程逐帧、逐像素相同。进程调度、资源加载、tween 和部分视觉随机数会产生时差。如需更严格的动画同步，还要传对应原版动画状态、进度和时钟，并逐类适配；不能把完整对局 hash 一致当作动画一致的证明。

.7 的连续出牌改善通过缓冲语义卡牌意图实现。动画期间能接收拖牌，状态一致后按原版规则执行。它减少被丢掉的操作，不等于把游戏结算移交给副本，也没有承诺消除全部动画等待。
