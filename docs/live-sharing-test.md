# 单人本地观战测试版

基于测试分支 `liveSharingTest`。模组版本：`0.3.9-liveSharing.6`。

## 安装与使用

1. 退出游戏，备份现有 `mods/RMPStable` 中的 DLL、PCK 和 JSON。
2. 将测试 ZIP 内的 `RMPStable` 文件夹放到游戏的 `mods` 目录，覆盖这三个文件。
3. 启用模组，进入单人游戏。在游戏窗口按 **F8** 打开游戏内观战面板，再按一次关闭；面板右上角使用原版叉形纹理的红色关闭按钮也可以退出，支持悬停放大和按下反馈。
4. 在游戏 **设置 → 输入** 中找到 **本地观战面板（单人测试）**，可以修改快捷键。设置沿用游戏原生保存与冲突处理机制。
5. 点击观战面板顶部的原版牌组图标，可以浏览本地只读牌组；再次点击返回当前页面。四个原版排序按钮支持升降序，滚轮和滚动条支持浏览，勾选“查看升级”可以比较升级后的牌组。
6. 悬停卡牌显示放大图和关键词解释；点击打开详情，可查看升级或基础版，并用左右箭头切换。第一张没有上一张，最后一张没有下一张。
7. 新用户面板默认宽度为原最小宽度 640 个逻辑像素的 5/6（约 533），默认水平居中，面板顶边位于原版第一行遗物高度的 3/5 处，露出遗物行上方 3/5、遮挡下方 2/5，不遮挡最上方状态栏。最小限制也为 5/6；已有布局恢复上次的位置及大小，并限制在当前屏幕范围内。拖动标题栏可以移动，拖动右下角可以调整大小；内部始终以 **1920×1080** 绘制，再按 16:9 显示。实况放入独立裁剪区域，左右和底部边框等宽，标题背景直接接到画面，没有额外黑色间隙；移动、缩放时不会越出弹框。面板外可以继续操作原游戏，面板内仅提供只读浏览，点击不会传给底层游戏。

8. 顶部为来源选择栏，依次排列原版卡牌详情左箭头、最多三个玩家框和右箭头。玩家框使用深蓝底色、更深的蓝色边框及白字，保留搜刮奖励框的图案。当前选中项直接使用搜刮金币奖励框的原版蓝色，未选中项使用稍浅于边框的深蓝底色；不添加黄色线或额外内描边，所有框均保留更深的蓝色外边框。每页三个，首/末页对应箭头灰色禁用，空余玩家框隐藏；长名字省略显示，悬停可查看完整名称和数值 ID。默认尺寸下框高 26 个逻辑像素，上下各留出 7 像素；框宽最多 150 像素，三框加箭头时也为拖动保留至少 96 像素空白。手动缩放面板时，整个导航栏（框、箭头、名字及红叉）按同一比例缩放，栏高和红叉右上角位置同步计算；红叉只在自己的按钮区域内显示。

9. 新存档档案默认关闭。F8 或红叉显式关闭会记住关闭状态；F5 重载、退回菜单、下一局和游戏重启恢复上次的开闭状态、大小、位置及来源。偏好写入游戏原生账号/档案目录中的 `rmp-spectator.json`，独立于局内存档和快速 SL 检查点；不同档案各自保存。

10. 拖动标题空白区域到游戏画面的左、右、上、下边缘后松开，可吸附收纳。鼠标移开约 0.45 秒后，面板以 0.24 秒平滑滑入对应边缘，只留 10 个逻辑像素的细条；悬停细条时平滑滑出，移开后再次收纳。右上图钉点击后变为金色直立样式并保持展开，再点击取消固定。拖离边缘恢复普通浮动面板。吸附方向、完整展开的位置、尺寸和固定状态按档案保存，收缩动画的位置不会覆盖正常布局。屏幕尺寸变化时重新贴边。当前仍是游戏内嵌面板：窗口模式下吸附游戏画面的边缘，全屏时对应屏幕边缘。

本版修正了卡牌详情和牌组升级复选框的鼠标命中区域，包括抽牌、弃牌、消耗牌堆中的详情；战斗手牌悬停放大后下端贴住画面底部。原游戏打开全局遗物详情时同步显示，打开地图时按地图实际覆盖奖励页的层级采集。

11. 实况鼠标直接复用游戏原生光标资源，默认是经典黄色三角，按下鼠标、检查物品及地图绘画/擦除时跟随原生样式和热点；按源窗口尺寸换算大小。鼠标坐标每秒最多采样 30 次，独立于整页采集，观看侧沿用一个图形节点平滑移动；静止位置复用数据。坐标按游戏画面宽高归一化，包含会话、来源及递增序号，旧序号不会覆盖较新的位置。光标不会拦截面板点击；在观战面板内操作或本地浏览牌组、牌堆与详情时隐藏来源光标，避免把观看者的浏览位置当成被观看玩家的位置。当前五个模拟来源展示的仍是本机鼠标，真实队友鼠标尚需接入多人传输；此版没有增加网络发送功能，也不采集游戏之外的桌面鼠标。

按本次测试要求，来源列表为 **本人 + 四个模拟玩家，共五个**。第一页面三个，第二页面两个，可以实际点击箭头和名字检查布局。本人名称按原游戏的平台接口自动读取；额外项明确写为“模拟玩家”，悬停注明展示本机状态。五个来源均使用同一份本机单人状态，不代表连接了其他玩家。关闭再打开恢复上次所选的稳定来源 ID；当前本地模拟来源也会保存。来源请求与快照确认分开，收到对应 `SourceId` 的新快照才更新选中项。

未来双人联机只提供另一位玩家时，沿用同一栏，仅显示一个玩家框，两侧箭头禁用。本轮没有好友来源列表或多人数据传输。

新用户默认关闭。开闭状态、位置、宽度及所选来源 ID 按本机游戏账号和存档档位保存在独立的 rmp-spectator.json 中，不写入对局检查点。F5 快速 SL、退局与换局只暂停采集，进入有效单人局后自动恢复先前开启的面板；F8 和红叉显式关闭会保存关闭状态。进入多人游戏时暂停当前原型，保存偏好，本阶段仍没有多人传输功能。

测试包不附带正式版的 `update.cmd`，以免更新时被正式版替换。恢复正式版时，覆盖回备份的三个文件即可。

## 已实现的显示

- 原版顶部状态栏、生命、金币、药水槽、遗物和牌组数量。
- 战斗背景、角色与敌人的视觉资源、当前手牌及扇形布局。
- 游戏已经公开显示的敌人意图与伤害数字，不预测后续行动。
- 原版血条边框、生命值填充、格挡盾牌及状态图标；读取当前原版显示的尺寸、字体和颜色。
- 战斗能量球、抽牌堆、弃牌堆、消耗堆和结束回合的只读外观。
- 战斗中点击抽牌堆、弃牌堆、消耗堆可打开各自的原版牌堆浏览布局；悬停放大、点击详情，左右切换到边界停止。抽牌堆按原版排序展示，不公开实际抽牌顺序。
- 头像/进阶、生命、金币、药水及空槽、地图、当前房间类型、章节 Boss 和持有遗物的原版悬停介绍。点击持有遗物显示原版放大详情，按持有顺序切换，不循环。
- 全局弹框单独同步，包含 F5 快速 SL 确认；观战内的弹框仅显示，确认和取消仍在游戏本体操作。
- 商店背景与地毯、原版商品分区、价格、金币图标、折扣标签、遗物、药水和删牌服务图案。
- 抓牌候选的原版卡面与位置、遮罩、标题和额外选项文本。
- 战斗结束后的搜刮奖励、继续与跳过按钮的只读显示。
- 地图纸张、路径、节点、当前位置、图例及绘画/擦除结果；地图滚动跟随游戏窗口。
- 先古之民的背景、对话、全部当前选项、遗物图案和说明；选择后的卡牌展示，以及删牌、变化、升级等原版选牌/确认界面会跟随当前页面。所有游戏选择仍在原游戏窗口完成。
- 原版牌组排列、获得顺序/类型/费用/拼音的升降序排序、关键词说明和卡牌详情。本地浏览不会替队友执行任何选择。

当前页面和牌组中的所有游戏操作仍在原游戏窗口完成。观战面板不提供打牌、购买、删牌、抓牌选择或结束回合操作。

## 实现方式

`LocalSpectatorSource` 读取当前单人局和已存在的原版显示节点，将信息转换为不含 Godot 对象或游戏模型的 `SpectatorSnapshot`。正常本地观战直接传递完成的只读快照，不再每次经过 JSON 序列化/反序列化。快照按状态栏、背景、生物、页面、物品、候选、手牌和牌组划分版本；用逐字段精确比较复用未变化的数据，不依赖序列化字符串或哈希碰撞判断。

状态采集仍在游戏主线程进行，但将界面遍历、图像、文字和卡牌读取拆成可以跨帧推进的工作。每帧以 **2 ms 软预算** 推进，完成后提交快照；不能中断单次原版调用、垃圾回收或最终显示更新，因此不是硬性的 2 ms 上限。页面、房间或视口变化会取消旧工作；跨帧读取子节点时沿用已经捕获的父变换，避免地图滚动时层级错位。

牌组增删、升级、费用等事件和轻量状态变化触发刷新，完整采集完成后还保留 50–250 ms 的自适应轮询间隔，覆盖没有事件的修正值和显示变化。这个间隔不包含跨帧采集所花的时间，不能当作完整延迟保证。隐藏牌组复用短时缓存，浏览时重新读取；地图绘画/擦除另以 50 ms 间隔检查，不等待整张地图采集完成。关闭面板会停止采集并解绑卡牌、牌组订阅。

卡牌复用原版 `NCard` 视觉预制体，但始终保持 `Model == null`。角色和敌人只实例化 `NCreatureVisuals`。商店、血条、地图、事件和状态栏读取原版纹理、九宫格边框、字体、位置、颜色、着色器参数、绘制顺序和遮罩，重建为独立的显示节点。资源通过本地路径缓存复用，不传输图片或模型文件。每次采集只读取一次同一材质实例的参数，保留不同实例的颜色差异；观战材质单独创建，不修改原游戏材质。

显示节点按标识保留，位置、颜色、文字和参数更新已有节点；地图滚动只增删进入/离开显示范围的节点，手牌仅位置变化时不重建卡面。牌组只创建可见行及相邻缓冲行的卡牌，详情切换仍使用完整排序后的牌组。地图笔迹传递线段与擦除材质，只有线段变化才重绘独立透明画布，不读取原游戏的画布像素。骨骼待机动画继续按引擎绘制帧率运行，不随状态采集周期重新实例化。

牌组、卡牌详情、关键词提示复用原版场景的装饰部分。进入场景树之前去掉游戏脚本，只保留没有模型绑定的文字绘制类；独立按钮只操作观战面板。升级/基础版来自原版方法生成的脱离游戏的卡牌副本，副本不会绑定到显示卡牌。每次更换源页面会关闭本地详情并返回对应源页面。

参考原版的 `NCard`、`NMerchantSlot`、`NMerchantCardRemoval`、`NCreatureStateDisplay`、`NHealthBar`、`NTopBar` 和 `NCombatUi` 的实现。显示与操作逻辑混合的节点没有整体复制，例如原版删牌节点的购买回调和血条的生物事件订阅均没有接入观战面板。

面板使用游戏主窗口内的 `CanvasLayer` 和独立 `SubViewport` 绘制，没有第二个桌面窗口；沿用 F5 弹框的装饰资源思路，不注册阻止游戏操作的全屏模态遮罩。关闭时不采集游戏场景，不创建第二套显示节点。开启时需要额外的卡牌、骨骼动画与视口渲染资源。浏览面板不会让游戏主窗口失去焦点，切换到其他应用时原游戏的后台帧率、静音设置仍然生效。

## 当前边界

- 支持针对 v0.107.1 和 v0.111.0 分别构建，通过引导 DLL 自动选择实现。实际图形运行验证使用本机 v0.111.0；v0.107.1 的运行效果仍需要在该版本游戏中验证。
- 保留原版主要布局和静态外观，角色使用待机动画，不同步攻击、受击、死亡动画、粒子、音效或屏幕震动。
- 不承诺所有怪物变体的骨骼皮肤、临时染色以及第三方模组资源都完全一致。缺失资源会记录日志；读取异常时清空旧画面并提示状态不可用。
- 本轮补充地图、搜刮、先古之民及其后续选择界面。其他事件使用同一套可见页面重建逻辑，但尚未逐个验证每个事件、先古之民、选项和角色的全部组合；休息点等其他房间也未作为本轮完整验证范围。商店商品来自已生成的本地库存，原型不会主动生成商品。
- JSON 往返保留为开发验证入口（`RMP_SPECTATOR_TRANSPORT_TEST=1`），正常游玩不启用。当前快照包含本地节点标识，尚不是最终网络协议；未来仍需稳定实体标识、静态定义/增量消息及恢复机制。本轮没有加入多人传输。

本地验证能证明：同样的一份快照，可以在游戏内面板重建可用的只读界面。以后接入好友观战时，还需要发送角色状态以外的手牌、奖励、个人商店、页面类型与布局信息，并处理权限、游戏版本、资源匹配、更新顺序、断线和缓存；仅收到角色信息还不足以还原全部页面。
