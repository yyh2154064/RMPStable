# .16 多人第二阶段：真实队伍窗口与个人选择界面

2026-10-11。接续以 `.14` 为基线的 `.15` 第一阶段，只在 `multiInstanceTest` 开发。当前候选 `0.3.9-multiInstance.16`，等待用户手动验收。

## 窗口行为

多人对局默认 F8 打开观战窗口，沿用原版按键重映射。来源按钮显示实际连接的队员及平台昵称，不显示单人的七个模拟来源；未初始化平台时按真实队伍槽位显示“玩家 1”等名称。首次选择其他队员，后续记住多人来源，独立于单人模拟来源的偏好。

切换玩家会撤销旧订阅、关闭对应自有副本，启动新来源的原版 Replay 窗口。原版 Replay 的本地身份绑定到所选玩家，保留全部玩家槽位；角色位置和绘制顺序由原版决定。本体身份不变。F8 隐藏仅关闭外壳，副本和订阅继续工作，重新打开复用同一副本。标题栏重置重新订阅并恢复当前来源，不重载本体对局。

本阶段保持只读：控制按钮禁用，副本不发送游戏操作、玩家选择或房间决定。原版鼠标悬停可展示提示；多人窗口的点击浏览、键盘导航和远程操控未在本阶段开放。单人模式的控制偏好不会被多人只读状态覆盖。

## 个人 UI 通路

普通多人 Replay 会等待远端选择结果，不能据此自动显示所选角色的本地选择器。第二阶段保留原版远端等待和回放服务，捕获原版 `CardSelectCmd` 参数，将选择描述绑定到玩家 ID 和原版 choice ID；在等待时创建原版选择控件。

| 类型 | 原版显示控件 | 本轮真实触发 |
| --- | --- | --- |
| 手牌单选、多选 | `NPlayerHand` SimpleSelect | 坚毅+、准备+ |
| 手牌升级 | `NPlayerHand` UpgradeSelect 与原版升级预览 | 武装 |
| 网格候选 | `NSimpleCardSelectScreen` | 抉择悖论遗物开局 Hook |
| 战斗牌堆 | `NCombatPileCardSelectScreen` | 头槌弃牌堆选择 |
| 三选一 | `NChooseACardSelectionScreen` | 发现 |

来源每次更新发送 choice ID、类型、提示、最少/最多数量、手动确认/取消/跳过条件、候选序列、可选索引、已选索引和原版计时文本。候选牌、筛选函数及显示控件由相同原版动作重新生成；元数据只更新呈现，不成为游戏动作。候选序列及序列化内容匹配后才应用高亮，避免把旧选择或错误牌序映射到新页面。同名牌按当前候选序列索引识别。

手牌选中/撤销、升级预览、网格高亮和已选牌行顺序使用原版控件。快速取消并重新选中造成的顺序变化也要同步，不能只比较选择集合。副本中的点击、确认、跳过和取消选中入口被只读门禁拦截。只有原版 `PlayerChoice` 回放结果才能结束独立显示任务，并继续原版动作。历史已完成的选择直接回放结果，避免重建时闪出过期选择页。

元数据同时绑定检查点 generation 和事件进度，副本消费到对应事件后才更新个人 UI。来源切换关闭旧管道；重新同步重新生成未完成的选择器，恢复来源的选中项。没有修改来源 RNG、原版回放记录器或选择计数。

## 房间边界及限制

非战斗房间不在战斗回放日志内。本阶段仅发送房间边界通知，立即撤销旧战斗的可显示状态，隐藏旧副本画面并提示当前房间。通知可在副本认证前到达，认证后会补发；旧加载任务完成也不能重新显示已离开的战斗。

地图、事件、奖励、商店、火堆、宝箱、结算等多人页面尚未重建，特殊 bundle/其他选择器未覆盖。后续需要公共房间状态、私人页面与权限协议，不能沿用单人的本机操作日志。Steam 跨电脑、三名以上玩家、客户端之间路由，以及可见窗口在实际全屏/DPI 下的显示效果仍需验证。这里的原版界面层级检查为 headless 节点数据，不能替代用户的可见 UI 验收。
