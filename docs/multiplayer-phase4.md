# 多人第四阶段：原版非战斗房间

候选版本 `0.3.9-multiInstance.18`，以用户指定的 `.14` 为多人开发基线，继续第一至第三阶段的数据路由、原版界面和来源授权。第四阶段独立专项 **176 项通过（房主 88、客户端 88）**；用户最终验收仍待反馈。

## 数据通路

原版 CombatReplay 仅在战斗进行时记录动作、Hook、恢复和选择结果，战斗结束即停止记录，不能直接覆盖地图、商店、事件、火堆、宝箱和战后奖励。本轮新增独立的来源日志，不修改或重启原版录制器：在非战斗房间进入原版 Hook/初始化前保存检查点；在战斗结束生成奖励前建立已结束战斗的奖励检查点。检查点包含原版存档、房间描述、choice/reward/action/hook/checksum 编号。

订阅仍通过原版可靠多人消息及房主路由传递到观看者，再通过认证管道传给独立原版 Replay 进程。增量仅包含原版非战斗动作与固定语义的原版同步决策：个人事件选择、共享事件投票及房主决定、休息选择、奖励选择/跳过、购买/删牌及其他玩家的原版结果消息、开箱和继续。副本不加入真实房间、不保存、不自行决定投票胜者或地图移动；实际跨房间移动由来源的新检查点建立原版房间。

原版房间反序列化入口只覆盖部分房间类型，因此地图、商店、火堆、宝箱使用各自原版模型创建；事件及已结束战斗使用原版描述恢复。商店从房间进入前的玩家 RNG 生成所有原版库存，并按原版槽位选择本地库存。来源商店和网络对端的个人历史存在差异，完整结果 hash 必须与所选来源本体比较，不能替换为观看者自己的本体状态。

## 操作和个人界面

来源在当前房间生成临时操作 ID、控件路径和私人上下文。观看者只提交当前来源广告中的操作，来源再次校验身份、权限、generation/epoch、事件前缀、私人状态和原版合法性，然后调用来源本体的原版控件/同步入口。其他玩家的操作不作为全队空闲门槛；全队 hash 用于核对已同步结果。房间/检查点变化撤销权限，原版房主继续排序和判断全队进度。

商店使用原版商品槽，保留卡牌、遗物、药水、价格和库存；删牌使用原版异步牌组选择。火堆使用原版休息按钮和升级选择器。个人选择在 Replay 的原版等待任务旁创建原版界面，候选、选中、预览、取消跟随来源元数据，只有权威 choice 结果能结束等待。取消预览先执行原版取消（原版需要上一张选牌来恢复焦点），再更新选择集合。升级或删除必须由来源确认后改变真实牌组。

事件保持原版个人/共享规则；共享事件只消费来源的最终决定，副本不主动完成全队投票。开箱与遗物分配、奖励页以及地图旅行同样继续原版多人逻辑。地图打开、旅行可用性和商店展开状态跟随来源。原版通常在本体点击地图时提前绘制自己的投票；副本直接消费权威动作，因此另用原版刷新方法呈现所选角色自己的投票标记。非终端奖励跳过同步原版关闭页面流程，终端奖励继续则跟随原版打开地图。火堆仅交换立绘位置/朝向和绘制层级，将当前本体/副本自己的观察角色放到前面，不交换玩家集合、座位对象或同步槽编号。
