# .17 多人第三阶段：来源授权与原版战斗控制

2026-10-11。以用户指定的 `.14` 为功能基线，接续 `.15` 数据通路和 `.16` 原版窗口。在现有 `multiInstanceTest` 分支开发，候选 `0.3.9-multiInstance.17` 等待用户手动验收；继续开发不代表此前版本已验收。

## 使用和权限

多人战斗中默认 F8 打开窗口，选择真实队员，点击控制按钮申请。所选玩家本体显示申请人及“允许本场战斗”“拒绝”；明确允许后开放该窗口控制。自己的角色窗口直接授权，其他玩家不能自动授权。已授权时本体保留操作能力，并显示“撤销控制”。每个来源同时允许一个控制者，申请约 15 秒未处理则过期，可重新申请。

切回观战、隐藏/关闭外壳、切换来源或重建副本会释放对应订阅的控制权。战斗结束、房间或检查点变化、断线、来源变化、权限心跳超时也会撤权；权限不带入下一场战斗。控制心跳每秒发送，约 15 秒无有效心跳由来源撤权。发出状态数据本身不会延长权限。

## 操作通路

窗口仍为独立进程的原版 Replay 场景，保留原队伍槽位、同步编号及全队立绘；本地身份绑定所选角色，因此所选角色在窗口最前。第三阶段不重排玩家列表或修改本体身份，也不传输画面。

来源本体生成当前可用操作和目标的临时 ID；窗口仅发送授权轮次、检查点、单调操作编号、事件进度、私人上下文、操作 ID 和目标 ID。房主继续通过原版房间服务路由消息并排序原版动作，所选玩家本体验证权限和当前操作，再调用原版动作/控件。副本不先修改卡牌、药水、能量或选择结果，等待原版事件回放。

多人不能要求全队同时空闲或用全局 hash 作为出牌前提：其他队员的独立动作会改变全局状态。这里以所选玩家的手牌身份与内容、药水、能量、回合、个人选择和页面状态生成上下文；本体发起自己的原版操作时立即提高修订号，阻止尚未执行的旧请求。执行时重新检查当前卡牌、费用、阶段、目标和原版控件。全队 hash 继续用于结果同步核对。

| 操作 | 权威执行与限制 |
| --- | --- |
| 出牌、选择目标 | 原版 `TryManualPlay`，原版合法目标与费用检查 |
| 使用药水 | 原版 `EnqueueManualUse`，自身、队友、敌方目标；不开放丢弃 |
| 结束回合 | 原版 `EndPlayerTurnAction`，由原版处理全员回合推进 |
| 手牌单选/多选、升级、网格、战斗牌堆、三选一 | 当前原版候选控件的选择、取消选中及可用确认/跳过；最终 `PlayerChoice` 由原版同步 |

重复可靠请求只返回缓存结果，不重复执行；缓存之外的旧编号、过期权限、未来事件进度、已变化上下文、非法操作和目标均拒绝。权限变更会清理未提交卡牌、药水和目标选择。药水原版异步目标流程可能恰逢其他队员动作回放，因此缓存具体药水及目标，等待副本可输入；换回合/权限/检查点、药水消失或目标死亡立即取消，最长八秒。选牌和确认也保留具体操作 ID 及 choice ID，避免回放期间丢弃点击；切换选择页面、权限或检查点即取消，提交前重新匹配当前可用操作。
