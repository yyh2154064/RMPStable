# .19 多人死亡与结算绘图专项

状态：开发候选，自动化结果如下；尚未交付或获得用户手动验收。2026-10-12 起所有测试后台静默。

## 修复

原版战斗结算直接将现有角色 Visuals 移到结算层，不再触发死亡动画。副本此前只修改另建的结算状态，实际战斗节点仍站立。现在先更新实际原生节点的终局呈现、调用原版死亡动画，再打开原版结算。

致命战斗动作自身也会请求结算。副本屏蔽这次本地自动创建，等来源最终记录和最后动作执行完后只创建一次结算，避免第二个结算销毁已移走的角色，或最后的施法动画覆盖倒地姿态。没有调用额外的游戏死亡 Hook，也没有手绘角色或传输画面。

## 独立入口与范围

`tools/Test-MultiplayerDeathVisual19.ps1 -Outcome defeat|victory`，复用当前三人启动设施。原版 `.111` localhost ENet；铁甲战士、静默猎手、故障机器人；三个独立原版副本。隔离角色获得原版 Bloodletting，利用真实出牌动作的原版伤害/死亡流程测试单人死亡。defeat 分支现利用另外两名玩家各自出牌触发全队失败；victory 分支调用原版 WinRun 流程。

核对各玩家 HP、死活、实际 Spine 动画、角色交互/焦点、战斗血条透明度、角色所在 UI 层，以及所选来源的手牌显示。死亡后状态重置必须保持相同 PID、完整来源 hash 和原生呈现。结算检查三角色实际 die 动画、可见性、透明度、结果、所选角色和分数，并保存原版与副本稳定帧；原版截图暂时隐藏 mod 外壳以避免遮挡。源与窗口按所选玩家身份对照，角色前后顺序保留原版观察身份规则。

所有新增运行使用 F 盘既有 runtime、独立档案和隐藏启动宿主；验证原版 source 不可见，副本位于屏幕外约 (-29658,-29936)，静音、30 FPS、低优先级。只向游戏内部输入/动作队列发送测试操作，不操作系统鼠标、键盘或用户当前游戏。保存的 PNG 是实际 D3D12 原版渲染，不用于窗口传输。
