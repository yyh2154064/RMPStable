# v0.4.3 战斗牌堆及窗口交互专项

2026-10-17 用户反馈：队友窗口的许愿选牌和眼睛按钮不可交互，展开窗口中观战/操控切换失败，设置界面返回按钮不可交互。

## 实现

- 原版 `NCardGrid` 会回收并重用屏幕外的持牌控件。旧代码以 `CurrentlyDisplayedCards` 发布选牌候选，且只为来源当前已分配的控件发布操作；副本独立滚动后可能没有对应操作，候选/已选项也会随滚动变化。现在取网格的完整过滤、排序列表，发布全部合法卡牌操作，以网格路径、模型、升级级别和原列表索引定位。来源执行前仍验证租约、代次、上下文、任务未完成、实际牌堆成员和过滤条件，然后直接执行原版选择器回调；无需来源窗口先滚动或分配控件。专项还发现中距离卡牌在原版网格单次分配后仍不可解析，这一路径也由模型选择消除。
- 完整牌堆的相同元数据不再每帧重复入队；变化仍立即发布，稳定状态每秒保活，控制请求及确认直接发送。
- 空牌堆和自动选取完成后清理捕获；两个游戏版本的提前返回位置不同，有的已预留选择 ID、有的尚未预留，因此同时清理未预留及已预留但未打开选择器的捕获，异步完成也沿用原版任务结果及 UI 上下文。
- 多选同步只高亮新加入的牌，防止重复高亮导致取消选择后仍留有高亮。
- 牌堆选择器的眼睛按钮接入本地展示输入，不提交选牌决定、不结束来源选择任务，也不写入操作日志。
- 原先的 `PopupPanel` 提示即使不可聚焦，仍会捕获弹窗外点击。改用不捕获鼠标的原生提示窗；模式按钮点击依据会话状态发出下一请求，不再每帧覆盖按下中的切换状态。
- 设置返回按原版 `NBackButton` 的实际按钮图像检测按下和松开，修复图像超出根控件矩形时无法点击。

仍使用独立进程原版界面，只传状态和操作，由来源进程权威判定。未加入画面传输或自绘游戏界面。

## 同类效果核对

在已有 F 盘原版参考源码中检索卡牌、药水、遗物的 `CardSelectCmd.FromCombatPile` 调用，共 13 张牌和 2 种药水：

| 来源牌堆 | 模型 |
| --- | --- |
| 抽牌堆 | Wish、SecretTechnique、SecretWeapon、SeekerStrike、Charge、Seance、Cleanse、DropletOfPrecognition |
| 弃牌堆 | LiquidMemories、Hologram、Dredge、NeowsFury、Graveblast、Headbutt、CosmicIndifference |

Headbutt、CosmicIndifference 选弃牌堆中的牌后放回抽牌堆。过滤、选择数量、自动完成和手动确认继续使用原版参数。上述参考源码未找到从消耗牌堆取牌的卡牌/药水调用；通用选择路径不限定 Draw/Discard，不能据此声称已运行不存在的原版取消耗牌实例。
