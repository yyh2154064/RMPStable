RMP Stable v0.3.7
=================

适用游戏版本：Slay the Spire 2 v0.107.1
最大联机人数：16 人

这是一个独立模组，不依赖其他多人联机扩容模组。

安装：
1. 不要同时启用其他多人联机扩容模组；请在模组菜单中禁用冲突模组，
   或暂时将其文件夹移出 mods 目录。
2. 将整个 RMPStable 文件夹复制到：
   Slay the Spire 2\mods\RMPStable\
3. 所有联机玩家都安装并启用同一个 RMP Stable 版本。
4. 建议房主重新加载存档后再让其他玩家加入；首次验证建议新开一局。
5. 后续更新可在关闭游戏后双击模组目录内的 update.cmd；脚本会从 GitHub 最新正式版
   中下载并替换 DLL、PCK、JSON，无需手动重新下载和解压 ZIP。

内置功能：
- 将多人联机人数上限提高到 16 人。
- 扩展大厅协议、玩家槽位及多人场景布局。
- 沿用游戏原生多人难度缩放，并提供商店、篝火、宝箱房与胜利流程适配。
- 删除导致 Reward ID 分叉的重复远端宝箱奖励生成器。
- 避免房间快照重复销毁远端输入同步器，防止 PeerInputMessage 错误刷屏。
- 使用协议 v3 的客户端握手补齐初始配置与房间快照，消除入房同步竞争。
- 暂停菜单新增“快速SL”，默认快捷键 F5，可在原版输入设置中改键。
- 单人快速SL直接载入原版检查点，不改写房间或奖励状态，过程中不会显示主菜单。
- 多人快速SL由房主确认；普通玩家自动重连并就绪，所有原成员到齐后房主最后自动就绪。
- 多人恢复会遮住内部主菜单过渡，仅在联机读档大厅建立后显示大厅。
- 每名普通玩家从收到快速SL消息起有独立的 9 秒完整恢复期限；寻找大厅、加入及等待读档大厅均计入期限。
- 普通玩家会在黑幕后依次打开原版多人模式和加入好友页面，自动重复点击原版“刷新”，优先加入房主，也可通过任意已回房的原成员好友加入同一大厅。
- 房主遮盖显示“正在初始化房间”；普通玩家遮盖会按自动流程显示“正在搜索房间”或“正在加入房间”，均复用原版加载提示且无需点击。
- 自动重连只有在真实进入读档大厅后才算成功；9 秒超时后会撤掉黑幕、退回“多人联机”页面并弹窗提示手动加入。
- 房主会等待旧 Steam 监听端口确认释放后再建房；自动建房失败时退回“多人联机”页面并弹窗提示手动读取存档建房。
- 更新器优先使用 Windows curl.exe，并提供 .NET 下载及仓库版本清单备用路径，不再依赖 Invoke-WebRequest。
- 更新器仅在 GitHub Latest 版本严格高于本地版本时替换文件；远端版本相同或更旧时不会下载、降级或覆盖。
- 适配 v0.107.1 的 SeedHelper.GetRandomSeed 新接口。
- 使用 RMP Stable 自有图标，以及重新编写的简体中文、英文界面资源。

资源说明：
RMPStable.pck 是本项目用 Godot 4.5.1 构建的独立资源包。
DLL 中的本地化路径也已改为 res://RMPStable/localization/。

同步问题修复原理：
当前游戏版本会在宝箱房中一次性为所有玩家生成房间结束奖励。如果远端开箱消息
再次生成奖励，房主和客户端记录的 Reward ID 数量及顺序就会不同，并在切换楼层时
触发“多人游戏数据不同步”。本模组不会注册该重复奖励处理器。

启动日志应出现：
[RMP Stable] Initializing standalone v0.3.7 for STS2 v0.107.1...

验证建议：
使用 5～6 人新局，经过至少一个宝箱房后连续切换若干楼层。如果仍然发生不同步，
请同时保留房主和至少一名客户端的同一局日志。

注意：当前成品已完成源码编译、程序集回查与静态兼容验证；快速SL的完整自动重连
仍需至少两台 Steam 客户端共同验证。
